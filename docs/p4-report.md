## 偏差与决策树使用记录

1. **受保护旧测试与法典矛盾（D1-3，有据修正）**：新聚光灯状态机（G8/G9）使 `tests/spotlight.spec.ts` 两个 P3 用例必然失败——①「无热情者仅一次 vacant」：宠物 b 热情度 50 属淡定，G9 要求 vacant + nap 同时发（新机返回 `[vacant, nap b]`）；②「无其他热情者到期续期不轮换」：G8 要求第 2 次到期发 excursion。手册"既有 8 用例全绿"的预测在这两点上不成立（模板间矛盾）。处置：这两个用例的断言**对齐法典新语义**并改注用例名（标注"取代 P3 基础版语义"），新增 spotlight2.spec 对新语义做穷尽覆盖。未删任何断言、未放宽容差。
2. **引擎模板真 bug 修复（updateExcursion，D1-3）**：溜达回场逻辑无条件把溜达者送回中央——若溜达期间持有者被点名/挑战顶替（G6 让位路径），被顶替者会被拽回中心冻结（浏览器实测复现：云子冻结于 x=99.488 长达 30s+，两次独立采样确认）。修复：回场前校验 `spotlight.getHolder() === id`，非持有者直接清除溜达状态（其站位已由挑战时的 assignSlots 边缘分派接管）。修复后第 4/5 项实验全绿。
3. **spotlight.ts 模板类型疏漏（D2）**：`durationOf(holder)` 处 `holder: SpotlightPet | null` 不可赋值（holderId 已在场校验，null 实际不可达）。修复：`holder !== null ? durationOf(holder) : opts.rotateMs` 类型兜底。
4. **手册"ArchiveEntry 是 Pet 结构超集"注记不成立（D2）**：ArchiveEntry 缺 `locked` 字段，直接传参报 TS2345。修复：图鉴回看时构造 `petView: Pet = { ...entry, locked: false }`（离场宠物无锁定语义，卡片也不展示锁态）。
5. **engine.ts 旧版残余报错**：CP2 改联合类型后，P3 版 engine 的 else 分支窄化失效报 5 个 TS2339——CP4 整文件覆写自然消除，未单独处理。
